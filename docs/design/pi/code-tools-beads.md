# Code tools, browser and beads

**Verdict:** Adopt `pi-lens` for code feedback, `pi-agent-browser-native` for browser work, and `pi-beads-companion` for Beads context and recovery. Keep the hard Beads protections as our own Pi port. Trial `pi-simplify` separately. Skip the Po hashline/grep packages for this Pi 1.6.0 + Bedrock setup: they don’t match Pi’s built-in tool protocol, and their current license is BUSL-1.1.

## Pick one

- **Beads context:** pick **`pi-beads-companion`** over `@maphew/pi-beads` and `@abix5/pi-beads`. Let Companion own policy/prime context and selected-issue recovery. Port and keep our own store/actor/write/claim/subagent/PR gates and six skills; remove any duplicate Pi prime/context injection. Do not treat Companion as a safety-gate replacement.
- **Browser runtime:** pick **`pi-agent-browser-native`** for local Pi browser work. `@onkernel/browser-loop` is a separate option for Kernel-hosted browsing and listed provider-native surfaces, not the default for Bedrock. Don’t enable both by default: they expose overlapping browser capabilities, though they are not technically exclusive.
- **Code feedback:** use **`pi-lens`** for diagnostics. **Trial** `/simplify` as a separate, explicit changed-code review command; it is not a substitute for the `code-challenge` or `quality` workflows.

## Hashline and grep decision

**Do not replace Pi’s built-in `read`/`edit`/`grep` with either Po package.** The current Po hashline protocol is not the OMP protocol described in `docs/design/hashline.md:9-14`: Po uses different file tags and line anchors, and Po grep is tied to Po’s native server/edit integration. The current releases are alpha and BUSL-1.1; Po grep’s own README says it needs a Po native server host ([hashline listing](https://pi.dev/packages/@agimon-ai/po-hashline), [grep listing](https://pi.dev/packages/@agimon-ai/po-grep)).

Keep Pi’s built-in grep for ordinary text search and our `ast-grep` skill for structural search. Keep the existing OMP hashline workflow where it is already used. For Pi, use built-ins as the baseline; only trial a **Pi-compatible** hashline implementation against Bedrock on a controlled task set. Test hashline for its stale-snapshot protection. The sources reviewed include no Bedrock comparison, so switching edit protocols now would be guesswork.

## Gaps where we still need our own plugin

- **Beads enforcement remains ours to port.** The three packages do not collectively reproduce our gates. In particular, keep the foreign-store/write-resolution policy, canonical store pin, embedded writer lock, gate admission, safe close/unclaim rules, actor attribution per subagent, claim confirmation and lease heartbeat/release, session/subagent lifecycle, PR-bead linkage, and execution-agent routing. See `plugins/beads/README.md:12-20,53-69,85-110,122-180,252-270,337-376`.
- **Keep our six Beads skills:** `beads-ledger`, `beads-evidence`, `beads-setup`, `beads-contention-retry`, `beads-preflight`, and `beads-guide` (`plugins/beads/README.md:180-213`; package source registers them in `plugins/beads/opencode/src/index.ts`). None of the three alternatives supplies these six.
- **Keep `code-challenge` and `quality`.** Pi Simplify is a narrow clarity pass; Pi Lens is automated feedback. Neither replaces challenge evidence/consent, our code-review policy, or test-audit workflow (`plugins/code-challenge/INVENTORY.md:3-4`; `plugins/quality/README.md:3-5`).
- **Keep the `design` review workflow.** The browser package supplies a means to drive the surface; `ui-review` still requires ARIA/computed-style/keyboard/width evidence (`plugins/design/README.md:22,33,76-78`).
- **If using `pi-agent-browser-native`, adapt** `ui-review/references/tools.md` to its `agent_browser` tool name and recovery behavior. The source instructions currently name browser tools generically (`plugins/design/README.md:76-78`).
