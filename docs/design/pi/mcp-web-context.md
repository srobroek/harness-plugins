# MCP, web, context and memory

**Recommendation:** Keep Pi’s built-in MCP as the default. Configure the existing servers in `~/.pi/agent/mcp.json`; do not install both MCP replacements. Adopt `pi-web-access` with the five search keys already named in fnox. Trial `pi-deferred-context-engine`, OpenWiki, Doc Bridge and DeltaBox only for their specific use cases. Skip `pi-memory` as a parallel memory store and skip `pi-openwiki-adapter` in favor of the official `openwiki` package.

## MCP choice and servers to move

**Use Pi built-in MCP first.** Pi documents stdio and Streamable HTTP support, per-server exposure and `${ENV_VAR}` expansion in `~/.pi/agent/mcp.json` ([Pi MCP docs](https://github.com/earendil-works/pi/blob/main/packages/coding-agent/docs/mcp.md)). Pi’s built-in starts enabled servers for a session; `pi-mcp-adapter` is the alternative if lazy connections matter. Do not install `pi-mcp-adapter` or `pi-mcp-extension` alongside each other or the built-in: extensions that own `/mcp` replace the built-in in sessions.

Move these configurations, using the actual `~/.pi/agent/mcp.json` user-level file:

| Server | Pi config and notes |
|---|---|
| `context7` | HTTP `https://mcp.context7.com/mcp`; optional header `CONTEXT7_API_KEY: "${CONTEXT7_API_KEY}"`. The `docs` plugin’s current URL/header contract is `plugins/docs/opencode/src/index.ts:5-19`. Our fnox config declares this key. |
| `openaiDeveloperDocs` | HTTP `https://developers.openai.com/mcp`; no key. The `docs` plugin keeps it off by default (`plugins/docs/opencode/src/index.ts:8-9`), so add it disabled unless you want it active. |
| `aws-mcp` | Stdio command `uvx`, args `["mcp-proxy-for-aws-cli@1.8.0","https://aws-mcp.us-east-1.api.aws/mcp","--read-only","--skip-auth"]`. Source: `plugins/aws/opencode/.mcp.json:3-5`. |
| `aws-pricing` | Stdio `uvx`, args `["--with","botocore[crt]","awslabs.aws-pricing-mcp-server@1.1.2"]`, env `AWS_REGION=us-east-1`, `FASTMCP_LOG_LEVEL=ERROR`. It is off by default in our OpenCode config. Keep `enabled: false` unless needed. |
| `lsp` | Stdio command `node`, args `["~/.local/share/lsp-tools-mcp/dist/cli.js","mcp"]`; use the pinned checkout commit in `plugins/lsp/README.md:37-45`. It supplies diagnostics, symbol navigation and rename; OpenCode’s result-appending behavior remains a separate plugin function (`plugins/lsp/README.md:3-6,13-14`). |

`Pi`’s built-in HTTP header expansion and child-process env settings can reference environment variables; do not paste credentials into the JSON. With the MCP adapter, Pi still reads standard MCP files, but the adapter’s own onboarding/config layer also applies.

## `pi-web-access`: exact search-key recipe

**Confirmed local key names; no values read.** OpenCode’s managed provider is `random` (our dotfiles OpenCode config). OpenCode’s documented `random` provider set is Exa, Firecrawl, Parallel, Tavily and TinyFish, using `EXA_API_KEY`, `FIRECRAWL_API_KEY`, `PARALLEL_API_KEY`, `TAVILY_API_KEY`, and `TINYFISH_API_KEY` ([OpenCode web-search docs](https://opencode.ai/docs/websearch)). OMP has `web_search.enabled: true` and `exa.enabled: true` in `~/.omp/agent/config.yml:758-760,831-833`; its provider order is not explicitly set there. OMP’s documented provider env names include Exa, Brave, Perplexity, TinyFish, Firecrawl, Tavily, Kagi, Jina and Parallel ([OMP environment variables: Web search](https://omp.sh/docs/env)).

fnox declares these names for the work and personal roles, without exposing their values: `BRAVE_API_KEY`, `EXA_API_KEY`, `FIRECRAWL_API_KEY`, `TAVILY_API_KEY`, `TINYFISH_API_KEY`, and `CONTEXT7_API_KEY` (our dotfiles fnox config). **`PARALLEL_API_KEY` is not declared in fnox**, so exclude Parallel from the confirmed route unless you add a managed secret. The other four search-provider keys plus Brave map directly to `pi-web-access`:

| Provider name in `pi-web-access` | fnox / process variable | `web-search.json` field if using file credentials |
|---|---|---|
| `exa` | `EXA_API_KEY` | `exaApiKey` |
| `brave` | `BRAVE_API_KEY` | `braveApiKey` |
| `tavily` | `TAVILY_API_KEY` | `tavilyApiKey` |
| `firecrawl` | `FIRECRAWL_API_KEY` | `firecrawlApiKey` |
| `tinyfish` | `TINYFISH_API_KEY` | `tinyfishApiKey` |
| `parallel` | `PARALLEL_API_KEY`: **not in fnox** | `parallelApiKey` |

`pi-web-access` reads `~/.pi/agent/web-search.json`; its README documents environment variable credentials, provider names, and that env vars take precedence over literal config values. Keep keys out of the file. To use the known providers in a deliberate order:

```json
{
  "searchRouting": {
    "providers": ["exa", "brave", "tavily", "firecrawl", "tinyfish"]
  }
}
```

Launch Pi so fnox supplies the process environment:

```sh
fnox exec -- pi
```

The package supports automatic fallback and also works with no API keys via Exa MCP; the routing above pins the set/order to the existing fnox-managed providers. `pi-web-access` requires Node ≥22.19 ([npm manifest and README](https://www.npmjs.com/package/pi-web-access)).

## Pick one

- **MCP:** built-in first. Trial `pi-mcp-adapter` only if start-up/process cost from enabled MCP servers is material. Never enable both MCP replacements.
- **Wiki:** choose official `openwiki` over `pi-openwiki-adapter`; the official package now ships its own Pi integration and is actively maintained. They are not compatible substitutes for each other’s UI/config, so do not install both.
- **Tool/context discovery:** choose one primary policy. DCE can coexist with other extensions, but avoid competing tool-promotion/search layers and install it last if adopted.
- **Context Mode vs. DeltaBox:** distinct functions, Context Mode externalizes output; DeltaBox can isolate filesystem operations when configured. Neither should be mistaken for the other or for a replacement for semantic permission rules.

## Gaps where we still need our own plugin

- `pi-web-access` supplies web/search/fetch, not the Context7/OpenAI docs MCP registrations or AWS MCP servers. Keep those server configs and the `aws-guidance` skill; migrate the server entries, not the OpenCode plugin runtime (`plugins/docs/opencode/src/index.ts:5-19`; `plugins/aws/opencode/.mcp.json:3-10`).
- `pi-memory` is not a Mnemopi bridge. Keep a Pi-specific session/memory adapter if cross-harness recall is required; none of the evaluated packages documents direct access to the current Mnemopi store.
- OpenWiki/Doc Bridge are not replacements for `session` or `agent-seance` transcript lookup (`plugins/session/opencode/src/index.ts:27-55`; `plugins/agent-seance/opencode/src/read.ts:2-18`).
- Keep `repomix` for explicit bounded bulk repo packing (`plugins/repomix/opencode/skills/repomix/SKILL.md:8-25`), `agent-efficiency` for oversized whole-file reads (`plugins/agent-efficiency/opencode/src/large-read.ts:14-16,97-103`), and `lsp` for post-edit diagnostics (`plugins/lsp/README.md:13-29`). The packages above only partially overlap those contracts.
- Doc Bridge’s Obsidian adapter can index selected human-authored project notes, but it is not a safe assumption that it should ingest or rewrite the user’s whole personal vault ([vault guide](https://github.com/AgentsKit-io/doc-bridge/blob/main/docs/guides/vault.md)).
