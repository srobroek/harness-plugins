# Plugin adoption on pi

Status: review, 2026-11-23. For each plugin in this repository: keep, drop or merge it, what replaces it in the adopted pi stack, what pi needs to adopt it, and what can be cut. The adopted stack is in [pi-migration.md](../pi-migration.md#recommended-stack).

## Summary

| Outcome | Count | Plugins |
|---|---|---|
| Drop: an adopted package or pi covers it | 8 | lsp (pi-lens), statusline (pi-statusline), docs (pi `mcp.json`), subagent-worktree (pi-subagents worktrees), ast-grep (pi-lens), session and agent-seance (pi-sessions), claude-compat |
| Move out of the harness plugins | 1 | plugin-audit (harness-kit command or repo script) |
| Partial: drop the runtime, optional small extension | 1 | model-roles (static per-role models in pi-subagents; extension only for tiers and fallback) |
| Skills, agent files or config only, each its own package | 18 | agent-coder, agent-mechanic, agent-researcher, agent-reviewer, build, lang-go, lang-python, lang-rust, lang-typescript, toolchain, eli5, repomix, aws, debate, project, architecture, quality, journeys |
| Needs a pi extension, large | 10 | safety, beads, parley, delivery, autopilot, speckit, code-challenge, design, cad, modes |
| Needs a pi extension, medium | 7 | trunk-dev, worktrunk, chezmoi, agent-efficiency, dep-update, find-tools, whats-new |

pi-subagents foreground children do not load the parent's extensions ([agents](https://github.com/nicobailon/pi-subagents/blob/main/docs/agents.md#tool-and-extension-selection)). Every gate extension (safety, beads, git policy) must be listed as a required extension for children.

### Cross-plugin merges

- **Shared agent conventions, separate packages:** `coder`, `mechanic`, `researcher`, the reviewer roles, `external-repo-worker` and the `modes` roles each ship from their own plugin package (owner decision). Keep distinct prompts, tool allowlists and `model` values, and share frontmatter conventions through the harness-kit pi target.
- **One shared review core and verdict contract:** preserve shared review policy as a skill, and keep the verdict format consumed by delivery rather than duplicating it across agent files ([agent-reviewer](plugins/agent-reviewer/README.md:15-20,51-59); [delivery verdict hook](plugins/delivery/opencode/src/index.ts:497-514)).
- **One orchestration runtime:** use pi-subagents for child execution and workflow fan-out. Use `contact_supervisor` for child-to-parent decisions; reserve `pi-intercom` for independent Pi sessions. If pi-intercom owns cross-session messaging, avoid also enabling pi-sessions messaging; in all cases disable pi-sessions’ own subagents feature ([pi-subagents](https://github.com/nicobailon/pi-subagents/blob/main/docs/configuration.md#tool-activation-lifecycle); [pi-intercom](https://github.com/nicobailon/pi-intercom#readme); [pi-sessions](https://github.com/thurstonsand/pi-sessions#readme)).
- **Use package capabilities narrowly:** `pi-simplify` is the quick simplification pass, `pi-plan-mode` the plan controller, `pi-sessions` the Pi session search/recall surface. Also `pi-advisor-flow` an optional advisor-not additional subagent runtimes or competing controllers ([pi-simplify](https://github.com/MattDevy/pi-extensions/blob/main/packages/pi-simplify/README.md). [pi-plan-mode](https://github.com/narumiruna/pi-extensions/blob/main/packages/pi-plan-mode/README.md). [pi-sessions](https://github.com/thurstonsand/pi-sessions#readme).
