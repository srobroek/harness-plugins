### Cross-plugin merges
- **Shared agent conventions, separate packages:** `coder`, `mechanic`, `researcher`, the reviewer roles, `external-repo-worker` and the `modes` roles each ship from their own plugin package (owner decision). Keep distinct prompts, tool allowlists and `model` values; share frontmatter conventions through the harness-kit pi target.
- **One shared review core and verdict contract:** preserve shared review policy as a skill, and keep the verdict format consumed by delivery rather than duplicating it across agent files ([agent-reviewer](plugins/agent-reviewer/README.md:15-20,51-59); [delivery verdict hook](plugins/delivery/opencode/src/index.ts:497-514).
- **One orchestration runtime:** use pi-subagents for child execution and workflow fan-out. Use `contact_supervisor` for child-to-parent decisions; reserve `pi-intercom` for independent Pi sessions. If pi-intercom owns cross-session messaging, avoid also enabling pi-sessions messaging; disable pi-sessions’ own subagents feature in all cases ([pi-subagents](https://github.com/nicobailon/pi-subagents/blob/main/docs/configuration.md#tool-activation-lifecycle); [pi-intercom](https://github.com/nicobailon/pi-intercom#readme); [pi-sessions](https://github.com/thurstonsand/pi-sessions#readme)).
- **Use package capabilities narrowly:** `pi-simplify` is the quick simplification pass, `pi-plan-mode` the plan controller, and `pi-sessions` the Pi session search/recall surface. `pi-advisor-flow` is an optional advisor, not an additional subagent runtime or controller.
